# 巷口奶茶铺 · Cocos Creator 3.8.8 原型

直接营业的横屏点击经营游戏。90 秒内争取 ¥150；三个顾客位、两个制作杯位、四种配方。随着完成订单数增加，解锁椰果和双拼，客流加快、耐心缩短。连续交付增加奖励，交错单、倒掉重做或顾客离开会打断连击。

## 首次运行（在编辑器操作一次）

1. 用 Cocos Creator **3.8.8** 打开本项目，等待脚本导入完成。
2. 在资源管理器新建 **Scene（2D 场景）**，命名 `Main`，双击打开。
3. 确认场景中有 **Canvas 和它的 Camera**（使用 2D 场景模板默认配置）。如果有模板示例文字，删除示例文字节点。
4. 选中 **Canvas**，将 `assets/scripts/TeaShop.ts` 拖到属性检查器，作为组件挂载。**只挂一次**，无需挂 `TeaGame.ts`。
5. 保存场景，预览当前场景。推荐预览尺寸 **1280 × 720**。界面运行时生成，编辑状态看不到是正常的。

无需制作 prefab、导入额外图片或手动绑定属性。默认 UI 相机须包含 UI_2D 层，Canvas 保留默认居中和缩放。代码使用 SHOW_ALL 适配，其他比例可能留边。正式构建时把实际使用的场景添加到构建场景列表并设为启动场景。

## 暖色手绘美术版

已有场景继续使用原来的 TeaShop 组件即可，等待 Creator 导入新增资源后重新预览。

- 店铺背景、4 位顾客、4 种配料道具使用内置 image_gen 生成，原图在 `assets/resources/art/`。完整生成提示词记录在根目录 `ART-PROMPTS.json`。
- 顾客和配料是 2×2 透明图集，代码创建 SpriteFrame 切出各格，无需在编辑器手动切图。背景 1672×941，两张图集各 1254×1254。保留透明通道。
- 增加顾客进场与呼吸动作、着急时轻微晃动、交付后开心弹跳和感谢文字。当前情绪通过动作、色调、文字呈现，尚未制作独立表情帧。
- 加料飞入杯子、液面平滑上升、封杯上下压合与进度条、成品飞向顾客、收益和连击浮字。杯子和动态液面继续用 Graphics 绘制，便于表现任意配方。
- 暂停同时冻结玩法和动画；切换到后台自动暂停，回来后点击继续。启动先加载美术，再开始营业计时。

### 手机试玩

采用 1280×720 横屏构图，底部配料和操作区高 126 设计单位。建议先通过 Creator 浏览器预览地址在同一局域网手机打开，手动横屏；手机须能访问电脑的 IP 和预览端口。正式原生构建时，在构建面板将设备方向设为横屏。网页端不强制锁定屏幕方向。

重点检查：16:9 和较长屏幕的文字可读性、拇指点击大小、刘海/底部手势条遮挡、快速交替操作两杯时的动画、后台返回暂停。当前是 SHOW_ALL 加边距方案，异形屏安全区仍需真机验收。素材总计约 6.4MB，移动端压缩和图集优化留待实测后处理。

## 操作

- 点击杯位选择当前杯子 → 红茶 → 鲜奶 → 按订单加入珍珠或椰果 → 封杯。
- 封杯需要 2.5 秒，此时可切换另一杯制作。
- 选中已封好的杯子，点击配方匹配的顾客交付。
- 配方必须完全匹配；错误交付扣顾客 5 秒耐心，杯子保留。倒掉重做不扣钱，但清空连击。
- 首单固定为原味奶茶。完成 2 单解锁椰果，完成 5 单解锁双拼。
- 右上角暂停；营业结束显示结果，可再开一局。

## 验证与试玩关注点

已进行脚本检查和独立规则测试，未启动 Creator 游戏或验证实际画面。

本机有 Node.js 和 TypeScript 时运行：

```sh
node tests/game.test.cjs
tsc --noEmit --skipLibCheck --ignoreDeprecations 6.0
```

第二条针对本机 TypeScript 6；其他版本可移除 `--ignoreDeprecations 6.0`。`skipLibCheck` 只跳过 Creator 引擎声明文件内部错误，仍检查项目脚本。

请先试玩一局，关注：双杯切换是否顺手、顾客等待时间是否合理、90 秒目标是否太简单或太难，以及是否出现画面/点击异常。出现报错时提供 Console 的第一条红色错误即可。

## 代码

- `assets/scripts/TeaGame.ts`：纯 TypeScript 规则、配方、客流、计时和结算，不依赖引擎。
- `assets/scripts/TeaShop.ts`：运行时界面、杯子绘制、点击交互、暂停和结果页。
- `tests/game.test.cjs`：临时编译玩法模块并验证主要规则，不启动游戏。

这是可迭代的单关原型：尚未加入存档、音效、拖拽、逐帧表情或升级系统。先验证美术和操作反馈，再扩展关卡。
